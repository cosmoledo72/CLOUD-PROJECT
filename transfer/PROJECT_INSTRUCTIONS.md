# Инструкции проекта CLOUD-PROJECT для Claude

> Скопируйте текст ниже (от «Проект» до конца) в поле «Instructions» (инструкции) нового проекта Claude на другом аккаунте.

---

Проект — CLOUD-PROJECT: портал совместной работы для ООО «ПАРТНЕР-ГАРАНТ» (аналог ONLYOFFICE CommunityServer). Стек: backend на Rust (axum, sqlx, PostgreSQL), frontend на SvelteKit 2 / Svelte 5 (adapter-static, SPA), редактор документов ONLYOFFICE Docs, развёртывание — Docker Compose + Caddy. Домен — cloud-project.online.

Код лежит на компьютере заказчика в D:\PROGRAMS\CLOUD-PROJECT. Подробный контекст для продолжения работы — в файле transfer/HANDOFF.md этой папки; техническое задание — docs/SPEC.md, дорожная карта — docs/PLAN.md, история решений — docs/CHAT_LOG.md (эти три файла также загружены в проект).

Постоянные правила:
1. Отвечать в чате на русском языке. Комментарии и описания в коде — на английском.
2. Никогда не изменять файл .env в корне проекта (там рабочие секреты заказчика).
3. Перед записью файла на компьютер заказчика сверять его md5 с последней версией в git (HEAD), чтобы не затереть ручные правки; после записи — проверять md5 записанного.
4. Каждая итерация начинается с короткого плана, который заказчик подтверждает. По вопросам оформления — предлагать визуальные макеты.
5. В каждой итерации: сквозные тесты scripts/*_test.py (новые сценарии — новые тесты), cargo test, svelte-check без ошибок и предупреждений, проверка интерфейса в браузере (светлая и тёмная тема, ширина телефона).
6. По итогам итерации обновлять SPEC.md, PLAN.md и CHAT_LOG.md и в папке docs/, и в документах проекта Claude.
7. Единый стиль интерфейса (SPEC, раздел 8ш): вкладки разделов `.tabs-line` с иконками; главная кнопка — справа на строке заголовка; ключевые показатели — StatTile в `.stat-grid`; фильтры списков — PickFilter/MultiFilter; пустые состояния — EmptyState.
8. После пересборки портала заказчик запускает `scripts\start.cmd local` (локально) или `scripts\start.cmd prod` (сервер офиса).
