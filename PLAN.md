Состояние на 10.11.2026. Архитектура и детали реализации описаны в [SPEC.md](SPEC.md).

**Как читать оценки.** Трудоёмкость дана в человеко-днях (чел.-дн.) для одного разработчика. Точность ±30%. Календарные даты рассчитаны от 16.11.2026 при пятидневной неделе и с учётом новогодних праздников.

## 2. Этапы

### Этап A. Пилотный запуск — ≈ 15 чел.-дн.

Цель: система работает на реальном сервере, и ей пользуются 3–5 сотрудников на настоящем проекте.

| № | Задача | Результат и критерий приёмки | Оценка | Приоритет |
|---|---|---|---|---|
| A1 | Окружение для запуска | Docker Desktop с WSL2 на рабочей машине или Linux-сервер (VPS в РФ). Обход ошибки 403 при установке WSL: загрузка с GitHub или ручная установка | 1 | Критично |
| A2 | Проверка интеграции с ONLYOFFICE Docs | Документ открывается; двое редактируют одновременно; после закрытия появляется новая версия; промежуточное сохранение работает; ошибки исправлены | 2–3 | Критично |
| A3 | Домен и HTTPS | Обратный прокси с сертификатом Let's Encrypt, отдельный поддомен для сервера документов, `COOKIE_SECURE=true` | 1–2 | Критично |
| A4 | Резервное копирование | Ежедневная выгрузка базы и файлов, хранение 14 дней, восстановление проверено на чистой машине | 1–2 | Критично |
| A5 | Наполнение портала | Реквизиты, фирменный стиль, 3–5 рабочих шаблонов (титульный лист, акт осмотра, программа обследования, сопроводительное письмо), пользователи и группы | 2 | Высокий |
| A6 | Пилот | Реальный проект ведётся в системе 1–2 недели, замечания собраны в список | 5 (календарно) | Высокий |
| A7 | Исправления по итогам пилота | Критичные и важные замечания закрыты | 3 | Высокий |

### Этап B. CRM — ≈ 49 чел.-дн.

Цель: вести заказчиков и продажи в той же системе, что и проекты. Полный цикл: запрос → коммерческое предложение (КП) → договор → проект → акты → оплата. По функциям это аналог CRM-модуля ONLYOFFICE CommunityServer, адаптированный под проектное и изыскательское бюро.

Этап идёт сразу после пилота. Разработку можно начать параллельно с пилотом: задачи A5–A7 в основном организационные. В этап перенесены уведомления и отправка писем — без них не работают напоминания по сделкам.

| № | Задача | Результат и критерий приёмки | Оценка | Приоритет |
|---|---|---|---|---|
| B1 | Контрагенты | Организации и контактные лица; реквизиты (ИНН, КПП, ОГРН, адреса, банк); поиск дублей по ИНН; импорт из XLSX/CSV; по желанию — автозаполнение по ИНН через внешний сервис (DaData) | 5 | Высокий |
| B2 | Права доступа в CRM | Видимость контрагентов (все, ответственный, группа); роль «Менеджер по продажам» | 2 | Высокий |
| B3 | Сделки и воронка продаж | Настраиваемые этапы (запрос, КП, тендер, договор, выполнение, закрыта); доска воронки с перетаскиванием; сумма, вероятность, ответственный, срок | 6 | Высокий |
| B4 | Связь с проектами | Проект создаётся из выигранной сделки с переносом данных; реквизит «Заказчик» ссылается на контрагента; в карточке контрагента видны его проекты и сделки | 4 | Высокий |
| B5 | История взаимодействий | Звонки, встречи, письма, заметки и файлы в ленте контрагента; поиск по ленте | 3 | Высокий |
| B6 | Почта: SMTP, приглашения, сброс пароля | Настройка почтового сервера портала; письмо-приглашение сотруднику; восстановление пароля по ссылке | 2 | Высокий |
| B7 | Уведомления | В приложении (обновление в реальном времени) и по email: назначение, приближение срока, просрочка, упоминание; пользователь настраивает их сам. Используются и в CRM, и в проектах | 5 | Высокий |
| B8 | Напоминания по CRM | Задачи по контрагентам и сделкам («перезвонить», «отправить КП») с уведомлениями о сроках | 2 | Высокий |
| B9 | Документы продаж | КП, договоры, счета и акты выполненных работ из шаблонов с метками `{{client.*}}` и `{{deal.*}}`; автонумерация документов | 5 | Высокий |
| B10 | Счета и оплаты | Статусы «выставлен», «оплачен», «просрочен»; этапы оплаты по договору; дебиторская задолженность по контрагенту и проекту | 5 | Высокий |

## 4. Риски

| Риск | Влияние | Мера |
|---|---|---|
| Интеграция с ONLYOFFICE не проверена вживую | Возможны ошибки сохранения при совместном редактировании | Задача A2 — первая; сценарии сохранения покрыты тестом |
| Ограничения загрузки из РФ (WSL, Docker Hub, обновления) | Задержка запуска | Ручная установка WSL; зеркала реестра Docker; размещение на VPS в РФ |
| Лицензия ONLYOFFICE (AGPL, до 20 подключений в бесплатной версии) | Нельзя продавать SaaS на бесплатной версии | Для внутреннего использования хватает бесплатной; для SaaS — коммерческая редакция (D9) |
| Персональные данные (152-ФЗ); в CRM их особенно много: контакты заказчиков | Юридические риски | Хостинг в РФ, документы по обработке ПДн и согласия (D9), разграничение доступа в CRM (B2) |
| Один разработчик | Сроки и «узкое горлышко» по знаниям | Документация (SPEC, PLAN), автотесты, CI |
| Рост объёма файлов | Нехватка места, медленные выгрузки | S3/MinIO (D1), контроль квот, корзина с автоочисткой |
| Платные внешние сервисы (автозаполнение по ИНН) | Расходы, зависимость от поставщика | Функция необязательная, по умолчанию отключена; ручной ввод реквизитов работает всегда |

## 5. Порядок работы над каждой итерацией

1. Согласовать состав итерации: задачи из таблиц выше.
2. Разработка; новые сценарии покрываются сквозными тестами в `scripts/`.
3. Прогон всех тестов: `cargo test`, `svelte-check`, `scripts/*_test.py`.
4. Проверка интерфейса в браузере (светлая и тёмная тема, мобильная ширина).
5. Обновление SPEC.md и этого плана; перенос изменений в рабочую папку.
6. Приёмка: показ на тестовом портале, затем обновление рабочего сервера (`docker compose up -d --build`; миграции базы применяются автоматически).
