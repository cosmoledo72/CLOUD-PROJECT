**Обозначения в каталоге:** ✓ — сделано; ◐ — сделано частично; «X → Y» — задача X вошла в задачу Y; ✗ — исключено из плана.

## 6. Риски

| Риск | Влияние | Мера |
|---|---|---|
| Интеграция с ONLYOFFICE не проверена вживую | Возможны ошибки сохранения при совместном редактировании | Задача A2 — первая; сценарии сохранения покрыты тестом |
| Ограничения загрузки из РФ (WSL, Docker Hub, обновления) | Задержка запуска | Ручная установка WSL; зеркала реестра Docker; размещение на VPS в РФ |
| Лицензия ONLYOFFICE (AGPL, до 20 подключений в бесплатной версии) | Нельзя продавать SaaS на бесплатной версии | Для внутреннего использования хватает бесплатной; для SaaS — коммерческая редакция (D9) |
| Персональные данные (152-ФЗ); в CRM их особенно много: контакты заказчиков | Юридические риски | Хостинг в РФ, документы по обработке ПДн и согласия (D9), разграничение доступа в CRM (B2) |
| Один разработчик | Сроки и «узкое горлышко» по знаниям | Документация (SPEC, PLAN), автотесты, CI |
| Рост объёма файлов | Нехватка места, медленные выгрузки | S3/MinIO (D1), контроль квот, корзина с автоочисткой |
| Платные внешние сервисы (автозаполнение по ИНН) | Расходы, зависимость от поставщика | Функция необязательная, по умолчанию отключена; ручной ввод реквизитов работает всегда |
| Библиотека чтения DWG молодая (`acadrust`, активно меняет API) | Ошибки отображения отдельных чертежей | Закрепить версию; прототип на реальных чертежах до встраивания (X1) |
| Объём плана вырос на этап F | Сдвиг сроков | Волны 1–2 дают главную пользу бюро; волны 5–7 можно переставлять по необходимости |

## 7. Порядок работы над каждой итерацией

1. Согласовать состав итерации: задачи из таблиц выше.
2. Разработка; новые сценарии покрываются сквозными тестами в `scripts/`.
3. Прогон всех тестов: `cargo test`, `svelte-check`, `scripts/*_test.py`.
4. Проверка интерфейса в браузере (светлая и тёмная тема, мобильная ширина).
5. Обновление SPEC.md и этого плана; перенос изменений в рабочую папку.
6. Приёмка: показ на тестовом портале, затем обновление рабочего сервера (`docker compose up -d --build`; миграции базы применяются автоматически).
